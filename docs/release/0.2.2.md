# PooledMailKit 0.2.2

This patch corrects the reviewed connection lifecycle, acquisition-budget,
measurement exception-safety and numeric configuration defects. It preserves
the public sender/pool options API and conservative post-DATA retry policy.

## Fixed
- Reject and dispose connection creations completing after pool shutdown or an
  acquisition deadline. Track late completion ownership and settle pending
  counts exactly once so delayed work cannot overrun MaxPoolSize.
- Start the acquisition budget before minimum refill and cover asynchronous
  connection creation and keepalive. Caller cancellation stays cancellation;
  expiration remains pool exhaustion. Never return a late successful lease.
- Preserve active-host failure attribution when the acquisition budget cancels
  a pending connection, allowing the next request to fail over. Genuine caller
  cancellation and capacity-only expiration do not penalize a host.
- Start reconnect cooldown at observed failure time and notify waiting callers
  when warmup publishes idle capacity.
- Isolate optional metrics subscriber exceptions from SMTP outcomes, lease
  cleanup, connection accounting and disposal of remaining connections. A known
  accepted message remains accepted; metrics faults cannot trigger retries.
- Reject non-finite jitter, undefined socket-mode enum values and unsupported
  timer settings during configuration. Clamp computed retry/cooldown backoff
  to the supported timer range. Keep infinite operation timeouts supported.
- Use wide intermediate host-weight arithmetic to preserve equal-weight
  selection for large valid weights.

## Dependencies and symbols
MailKit remains 4.16.0. Pin patched PKCS 8.0.2 for net8.0 and 10.0.14 for net10.0;
update private build-only SourceLink to 10.0.303. The known NuGet audit findings
from the previous dependency graph are rechecked for this release. These version
choices follow the published [PKCS advisory](https://github.com/advisories/GHSA-846f-f764-76mx)
and [SourceLink advisory](https://github.com/advisories/GHSA-23fw-v26w-5fgq);
package audit is not a full exploitability assessment.

The regular .nupkg now includes matching Portable PDB files beside both
lib/net8.0/PooledMailKit.dll and lib/net10.0/PooledMailKit.dll. A separate
.snupkg is also produced. Validate DLL/PDB identity and package membership,
not only the presence of a symbols configuration property.

## Behavioral and deployment boundaries
Accepted configuration is now bounded by the actual timer API maximum
(4,294,967,294 ms); extremely long previously accepted settings are rejected
at startup instead of failing during retries. This is stricter validation,
not a new dynamic-configuration contract.

Async deadlines do not forcibly preempt arbitrary synchronous third-party
work. The profiler's synchronous pre-call delay may exceed elapsed budget,
but the late lease is rejected and cleaned up; no hard wall-clock preemption
claim is made. Metrics isolation covers exceptions, not a subscriber that blocks
forever synchronously. Dynamic mutation of options after construction remains
outside the validated contract.

Both net8.0 and net10.0 targets are retained. .NET 8 support ends 2026-11-10;
users must review actual deployed runtime servicing and migration to supported
runtimes. See the [official support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).
