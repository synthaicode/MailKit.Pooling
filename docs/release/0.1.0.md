# MailKit.Pooling 0.1.0 Release Notes

`MailKit.Pooling 0.1.0` is the first public package release.

This release establishes the initial supported API and the core operational
behavior of the library.

## Highlights

- SMTP connection pooling on top of MailKit.
- Bounded acquisition with explicit pool exhaustion behavior.
- Connection reuse, idle validation, keep-alive checks, and idle timeout handling.
- Retry classification that avoids blind retry after ambiguous post-`DATA` failures.
- Reconnect cooldown and reconnect suppression to reduce reconnect storms.
- Multi-host configuration with priority-based failover and same-priority weight distribution.
- Metrics for pool state, send results, retry, failure classification, and reconnect suppression.
- Docker-backed integration and stress validation using `smtp4dev`.

## Public API

The intended public API for `0.1.0` is limited to:

- `ISmtpSender`
- `SmtpPoolOptions`
- `SmtpHostOptions`
- `SmtpSendResult`
- `SmtpSendFailedException`
- `SmtpFailureClassification`
- `SmtpFailureKind`
- `SmtpSendStage`
- `ServiceCollectionExtensions`

Implementation-oriented types remain `internal` to reduce accidental extension
surface before later releases.

## Known Limits

- macOS TIME_WAIT observer has not yet been validated on a macOS runner or host.
- Manual stress remains opt-in and Docker-backed.
- The public API is intentionally narrow and may evolve before a future `1.0` release.

## Release Use

This release is suitable for early package consumers who want:

- MailKit-based SMTP connection reuse
- explicit retry and ambiguity handling
- bounded connection management
- multi-host SMTP failover behavior
- operational observability hooks

It is not positioned as a full notification platform or templating framework.
